# EQMOD-3 — The GEOMETRIC programme (new approach)

## Why a new approach
The EQMOD physical substrate is computationally empty (G131–G144): it cannot learn/compute; its only role
was memory, and even there it was decorative vs standard ML. The one genuine win was ANNEALING for hard
optimization (G145) — established Ising machines. So the physics dead-ended.

## The new substrate = a GEOMETRIC concept space (ML/LLM now allowed)
Redefine "substrate" as a learnable GEOMETRIC space where:
- **representation** = concepts/entities are points/vectors in a metric space,
- **relations** = geometric transformations (translation / rotation / flow),
- **learning** = positioning entities + shaping transformations from data (online, PC-scale),
- **UNDERSTANDING** = geometric COMPOSITION & inference (e.g. grandparent = parent∘parent; analogy =
  vector offset; entailment = containment) generalizing to UNSEEN cases.
Goal: a proper learning+understanding method on the user's PC, geometric, using ML/LLM where it earns its
place. Established methods (TransE/RotatE, geometric/graph ML, hyperbolic embeddings, word-vector analogies)
named as such; the contribution is the synthesis toward understanding, tested with held-out generalization.

## Discipline (kept from EQMOD)
Pre-register bars before each run; PASS/NULL/PARTIAL honest; name established methods; controls must
collapse; no post-hoc tuning. Autonomous until the user says Kill (kill-switch .eqmod_autonomy_off).
